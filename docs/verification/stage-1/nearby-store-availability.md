# 最近五家模拟门店与时段展示

日期：2026-11-02。此阶段只完成 C02 的**候选展示**，没有客户选店、真实车源查询、预约或工单分配。

后续已增加[客户选店代码与隔离测试](customer-store-selection.md)；本页保留当时“只展示候选”的验证记录。

## 数据与入口

- 六家门店坐标和 `MX-7` 在 `2026-11-07 14:00+08:00` 的虚构车辆、时段状态保存在 [`data/stores/simulated-v1.json`](../../../data/stores/simulated-v1.json)。该文件独立于评测输入 [`c02-v1.json`](../../../data/eval/store-selection/c02-v1.json)，两者均明确标为模拟。
- `NearbyStoreSelector` 先按直线距离取五家，再由 `SimulatedStoreCatalog` 查询这五家的状态。无车、满额和未知状态仍占最近五家的位置；第六家不会替补。车型编号和试驾时刻必须精确匹配模拟数据，其他输入返回未知，不能被标为可选。快照编号包含模拟数据的 SHA-256；数据改动后编号会变化。缺编号或超过 10 分钟的快照按未知处理。
- 管理员演示页 `http://localhost:8091/agent-demo.html` 新增“模拟查询最近五家门店”。先创建 Agent 任务，再用手填大致位置或浏览器定位查询。`POST /api/agent/nearby-stores` 只在三个演示 Profile 下注册，要求有效管理员 Session、同源 Origin 和 Session 绑定的 CSRF 令牌。位置只用于本次请求，不写入任务、工单、知识库或日志。
- 页面仅显示模拟结果，不提供“客户已选择”按钮。原有门店补充表单仍是管理员代录，不能当成客户本人选择。

## 验证

- `NearbyStoreAvailabilityServiceTest`：C02 六店输入得到 A、B、C、D、E；可考虑 A、C、E；B 无车、D 满额；F 不替补。模拟查询器故障或快照缺编号、过旧时，该店状态为未知且不可选；数据变动改变快照编号；非法位置、过去时间被拒绝；其他车型无可选状态。
- `NearbyStoreControllerTest`：有效管理员和 CSRF 可查询五家；普通用户、缺 CSRF 被拒绝。
- Java 21 容器运行默认 `mvn test`：119 例、失败 0、错误 0、跳过 28。新版本在本机 `8092` 启动后，应用内浏览器以既有管理员会话创建 Agent 任务并点击查询，页面实际显示 A、B、C、D、E 及上述模拟状态；这一步没有调用分配接口。正式本机端口 `8091` 已重新启动并显示新版页面；额外的 `8092` 验证进程已关闭。
