# 任务与只读预览接通记录

日期：2026-11-01。`AgentTaskWorkflow` 已把管理员身份检查、任务存储和只读预览串成 Java 内部流程。

## 实际行为

- `open` 通过业务系统 `/api/user/current` 取得管理员 ID，再读取待分配试驾工单，创建只属于该管理员的 Agent 任务。
- `find`、`supplement`、`refresh` 每次重新读取当前身份；普通用户、封禁用户或无效会话不得操作任务。任务表同时按管理员 ID 限制读取和版本更新。
- `refresh` 先比较工单编号、类型、状态、顾问和更新时间。变化时标记 `STALE_PROPOSAL`，停止政策检索。未变化时运行现有只读预览，将精简证据和工作量按任务版本保存。若计算期间有人修改补充信息，旧版本的保存会失败。
- 刷新过程中再次检查管理员身份；返回结果仍 `assignmentEnabled=false`。Cookie 仅在调用链中传递，不写入任务表。

## 验证与未跨过的门槛

隔离 PostgreSQL 探针共 12 例、失败 0，其中新增的任务流程 4 例覆盖：正常创建、补充和刷新；普通用户/其他管理员隔离；工单更新时间变化；预览计算中补充信息变化。Java 21 容器中的完整 Maven 默认测试为 84 例、失败 0、错误 0、跳过 17；跳过项主要是需要显式环境的数据库与真实模型测试。测试使用模拟身份和业务响应；不代表真实管理员 Session 联调。

当前没有任务 HTTP 写入口，也没有确认或分配。浏览器同源、Cookie、CSRF 与 `carSystem` 角色变化后的实时权限仍待联调；真实分配继续关闭。快照比较只能发现读取时已知的变化，确认前仍须重新读工单。
