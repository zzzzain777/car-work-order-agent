# 阶段 1：候选政策证据判断

本组件只针对仓库里当前的**模拟试驾政策**。输入为问题、可信的门店/车型/预约时间、原始政策列表以及检索返回的候选片段。它不直接调用模型、数据库或 `carSystem`。

处理顺序：先用结构化字段筛掉不适用的门店、车型、状态和生效时间；再判断问题是否属于当前试驾政策能覆盖的范围。价格、优惠、实时试驾车/空闲时段、证件等无依据问题返回 `NO_EVIDENCE`。同一范围有多份有效政策时，返回 `REVIEW_REQUIRED` 和全部原始政策引用，不让向量检索漏掉的另一份政策消失。单份政策只接受 ID、原文及关键元数据与当前语料一致的候选片段，并保留原始引用。

`CANDIDATES` 的含义是“候选片段可展示给后续回答步骤”，**不是**“问题已经被完整回答”。当前问法判断是小范围、保守的词面规则，不能覆盖任意表达，也不能验证生成答案中的每个事实。真正的 Embedding 召回、答案级引用支持、政策文本冲突识别和实时车源判断仍未完成；因此不能把本组件或测试说成完整 RAG 准确率。

验证入口：在 IDEA 运行 `PolicyEvidenceGateTest`；有 Docker 时运行 `bash probes/stage-1/java-pgvector-smoke.sh`，可检查 pgvector 返回的文档能否通过同一判断。原关键词挑战集和 6/8 记录保持原样，以便后续比较。

2026-10-29 本地实测：`PolicyEvidenceGateTest` 9 项通过；Java/pgvector 探针通过；无 Key、无数据库的默认全套测试共 47 项，0 失败、0 错误、2 项按预期跳过（真实 DeepSeek 调用与数据库探针）。这些结果验证的是组件行为和接线，**没有**测出语义检索准确率。
