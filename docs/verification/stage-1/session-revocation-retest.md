# 本机管理员权限撤销复测

日期：2026-11-02。此记录只针对本机 `carSystem:8080` 和 Agent `:8091` 的模拟测试账号；不包含真实工单分配。此前[阶段 0 联调矩阵](../stage-0/session-matrix.md)记录的是旧运行版本的失败结果，保留作失败案例。

## 运行版本与方法

- `carSystem` 源码中的 `LoginInterceptor` 已有未提交的修改：受保护请求从 Session 取用户 ID，再从数据库读取当前角色与状态；封禁时使 Session 失效。本次重新编译当前工作区，使用 Java 8 启动生成的 JAR，确认 `:8080` 登录页恢复 HTTP 200。没有改动 `carSystem` 源码，也没有将其工作区修改提交。
- 用独立 HTTP 会话登录模拟管理员与普通用户。对模拟管理员先验证正常请求，再分别临时将其角色改为普通用户、将状态改为封禁；每项测试在 `finally` 中恢复数据库。只记录状态码和业务码，不保存口令或 Cookie 值。
- 浏览器使用的既有会话没有被拿来改角色；测试使用另开的会话。Agent 与 `carSystem` 都接收同一 `localhost` 主机名下、`Path=/api` 的 `SESSION` Cookie。

## 实测结果

| 场景 | `GET /api/user/current` | `GET /api/workOrder/workload` | `GET :8091/api/agent/tasks/csrf` |
|---|---|---|---|
| 管理员正常登录 | HTTP 200，业务码 `0`，角色 `2`、状态 `0` | HTTP 200，业务码 `0` | HTTP 200 |
| 同一旧会话，管理员降为普通用户 | HTTP 200，业务码 `0`，角色即时变为 `0` | HTTP 200，业务码 `40102` | HTTP 403 |
| 新会话登录后，该账号被封禁 | HTTP 200，业务码 `40301` | HTTP 200，业务码 `40100` | HTTP 401 |
| 账号恢复正常后，继续使用封禁前旧会话 | HTTP 200，业务码 `40100` | HTTP 200，业务码 `40100` | HTTP 401 |
| 普通用户正常登录 | HTTP 200，业务码 `0`，角色 `0` | HTTP 200，业务码 `40102` | HTTP 403 |

复核数据库：模拟管理员恢复为角色 `2`、状态 `0`；模拟普通用户为角色 `0`、状态 `0`。这证明**本机当前运行版本**对上述降级、封禁及旧会话失效场景生效。此前的失败原因是运行中的旧编译结果没有包含已写在源码中的拦截器修改。

## 仍未跨过的门槛

- `carSystem` 的权限修复尚未提交，也未验证其他部署会运行这个版本。自然过期和多设备会话尚未实测。
- Agent 仍缺少完整工单标题和内容快照；顾问门店归属、真实车源与时段不可从当前接口核实。分配接口没有版本或幂等入参，读后写之间存在并发变更风险。
- 因此只把**本机权限撤销子项**改为通过；真实分配仍关闭，页面批准只走固定拒绝的模拟端。
