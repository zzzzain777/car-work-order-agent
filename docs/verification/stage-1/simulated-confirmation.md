# 模拟人工确认与结果未知处理

日期：2026-11-02。这里验证的是 Java 内部流程和隔离 PostgreSQL 中的状态，不包含真实 `carSystem` 分配请求。后续加入的[本机演示入口](local-demo-entry.md)只接固定拒绝的模拟端；生产应用没有注册真实分配适配器。

## 已完成的流程

1. 只接受刚刚刷新、且经过程序校验的候选建议。把建议顾问、任务版本、模拟政策内容摘要及 10 分钟有效期写入 Agent 自己的提案表。提案发布通过任务版本条件更新，不能拿旧建议覆盖新任务。
2. 管理员确认带回 `proposalId` 和提案版本。先检查管理员身份、任务归属、版本与有效期；拒绝和过期提案不会调用模拟分配。过期提案转为 `STALE_PROPOSAL`，可重新补充信息和取证。
3. 批准时，在同一个本地数据库事务内把任务从 `AWAITING_CONFIRMATION` 抢占到 `REVALIDATING`，并写入唯一的一次尝试。重复或并发确认读取该尝试，不创建第二次调用。
4. 调用模拟分配前，重新读取工单、模拟政策、顾问名单和工作量，再核对管理员身份与工单。原工单快照、政策来源及原文摘要或目标顾问已变化时，旧建议失效。
5. 模拟端明确接受且复读工单观察到目标顾问时，记 `SUCCEEDED`；明确拒绝且工单未变化时，记 `DEFINITELY_FAILED`。调用异常、超时或响应与复读结果不一致时，记 `OUTCOME_UNKNOWN`。超时后的复读仅用于记录观察结果；即使看到目标顾问，也不能单凭这次读取证明本次调用导致了变化，更不会自动再发一次请求。
6. 对中断前已持久化、但仍停在 `REVALIDATING` 或 `EXECUTING` 的尝试，提供显式恢复操作：运维确认没有活跃调用后，按最后活动时间把它们保守标为 `OUTCOME_UNKNOWN`。恢复不会重发分配。

## 验证边界

`SimulatedConfirmationProbeTest` 使用临时 PostgreSQL、固定政策及模拟业务端，覆盖正常确认、重复确认、并发确认、工单变化、政策原文变化、超时、超时后观察到目标状态、拒绝、过期、跨管理员访问和中断恢复。运行入口为 `bash probes/stage-1/java-pgvector-smoke.sh`。模拟端在隔离测试中注入可控结果；网页使用固定拒绝的模拟端。代码中没有真实 `POST /api/workOrder/assign` 适配器。

2026-11-02 在 Java 21 容器中运行默认 Maven 测试：100 例、失败 0、错误 0、跳过 28（含需显式启用的数据库和外部模型测试）。另用临时 PostgreSQL 显式运行 23 例数据库探针：失败 0、错误 0、跳过 0；其中模拟确认 9 例。

2026-11-02 的浏览器联调已证明正常管理员 Session、任务写入口和 CSRF 可一起工作；缺令牌、跨源、跨会话及普通用户反例也被拒绝。但用新建测试管理员实测，角色降级或封禁后，**当前运行中的 `carSystem` 旧 Session 仍保留管理员权限**，Agent 再次请求 `/user/current` 也会误认为有权。工单只读 DTO 还缺标题与内容，无法覆盖设计中的全部快照字段。顾问门店归属和试驾车源仍是模拟或未核实数据。因此不能宣称真实安全分配已完成。后续要先补齐下游的权限撤销和数据契约，再决定是否接真实写入。评测结果只按固定案例和实测值报告。
