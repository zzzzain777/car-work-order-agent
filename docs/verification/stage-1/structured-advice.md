# 模型结构化建议与引用核验

日期：2026-11-01。`AgentAdviceOrchestrator` 已连接“任务刷新 → 只读证据 → 模型候选建议”，仅在同时启用 `policy-rag,deepseek` 配置组时创建模型建议 Bean。当前仍是 Java 内部流程，没有浏览器任务写入口或分配接口。

## 边界

- 只读预览未到 `READY_FOR_ADMIN_REVIEW`、任务中的证据摘要与本次结果不一致，或缺政策/顾问数据时，模型不会被调用。
- 模型通过 Spring AI 的 `ChatClient` 收到分开的系统规则与用户数据。用户数据只有工单编号、Agent 补充的门店/车型/时间、模拟政策原文与来源、顾问编号及工作量；不含 Cookie、管理员 ID、顾问姓名或客户信息。
- 模型只返回 JSON 中的候选顾问编号及 1–3 条 `{sourceRef, quote}`。程序拒绝多余字段、JSON 后追加文字、未知顾问、伪造来源、非原文短引、重复来源及超长响应。建议文字由 Java 使用已核对的工作量生成；政策只展示可回到模拟原文的短引。
- 失败返回 `NEEDS_REVIEW`，不生成候选顾问；成功返回 `CANDIDATE`，仍须管理员核对顾问门店归属。两种结果均不具备确认或分配能力。响应保留提示词版本、模型名与 Token 用量字段，供后续评测使用；模型原始输出不作为执行命令。

## 验证范围

`StructuredAdviceServiceTest` 使用固定模型输出覆盖有效建议、非就绪停止、伪造顾问/出处/短引、额外字段、Markdown、JSON 后追加内容和模型异常。`DeepSeekFrameworkIntegrationTest` 使用本机假 DeepSeek 服务验证系统消息与用户消息分开发送，不消耗真实 Key。隔离 PostgreSQL 探针验证从持久化任务刷新到候选建议的连接，并验证缺字段时不调用模型。

Java 21 容器中的完整 Maven 默认测试为 91 例、失败 0、错误 0、跳过 19；显式运行的隔离 PostgreSQL 探针为 14 例、失败 0、错误 0。

这一步验证的是**结构与引用边界**，尚未评测真实模型的建议质量，也未持久化最终模型候选。后续固定案例评测应记录逐例输出与失败原因；展示简历项目时不能把这些模拟测试算成真实业务成功率。
