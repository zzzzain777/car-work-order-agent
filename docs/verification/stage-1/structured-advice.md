# 模型结构化建议与引用核验

日期：2026-11-01；2026-11-03 补充同范围多片段的引用边界。`AgentAdviceOrchestrator` 已连接“任务刷新 → 只读证据 → 模型候选建议”，仅在同时启用 `policy-rag,deepseek` 配置组时创建模型建议 Bean。当前有浏览器任务入口与模拟确认，真实分配仍未开放。

## 边界

- 只读预览未到 `READY_FOR_ADMIN_REVIEW`、任务中的证据摘要与本次结果不一致，或缺政策/顾问数据时，模型不会被调用。
- 模型通过 Spring AI 的 `ChatClient` 收到分开的系统规则与用户数据。用户数据只有工单编号、Agent 补充的门店/车型/时间、模拟政策原文与来源、顾问编号及工作量；不含 Cookie、管理员 ID、顾问姓名或客户信息。
- 模型只返回 JSON 中的候选顾问编号及一条 `{sourceRef, quote}`。程序拒绝多余字段、JSON 后追加文字、未知顾问、伪造来源、非原文短引及超长响应。建议文字由 Java 使用已核对的工作量生成；政策只展示可回到模拟原文的短引。
- 失败返回 `NEEDS_REVIEW`，不生成候选顾问；成功返回 `CANDIDATE`，仍须管理员核对顾问门店归属。两种结果均不具备确认或分配能力。响应保留提示词版本、模型名与 Token 用量字段，供后续评测使用；模型原始输出不作为执行命令。

## 验证范围

`StructuredAdviceServiceTest` 使用固定模型输出覆盖有效建议、非就绪停止、伪造顾问/出处/短引、额外字段、Markdown、JSON 后追加内容和模型异常。`DeepSeekFrameworkIntegrationTest` 使用本机假 DeepSeek 服务验证系统消息与用户消息分开发送，不消耗真实 Key。隔离 PostgreSQL 探针验证从持久化任务刷新到候选建议的连接，并验证缺字段时不调用模型。

Java 21 容器中的完整 Maven 默认测试为 91 例、失败 0、错误 0、跳过 19；显式运行的隔离 PostgreSQL 探针为 14 例、失败 0、错误 0。

这一步验证的是**结构与引用边界**，尚未评测真实模型的建议质量，也未持久化最终模型候选。后续固定案例评测应记录逐例输出与失败原因；展示简历项目时不能把这些模拟测试算成真实业务成功率。

2026-11-02 浏览器联调发现业务系统返回 85 位顾问，原有“超过 50 位就整体拒绝”的保护会让建议流程在调用模型前停下。现在完整顾问列表仍进入 Agent 任务快照并用于前后核对；模型只看按处理量、顾问编号确定性排序的前 50 位，解析后也只接受这 50 位中的顾问。固定测试覆盖超过上限时生成候选及拒绝名单外编号。一次真实 DeepSeek 调用虽已到达模型，但返回内容未通过候选或原文短引校验，故转人工核对；没有把这次运行算成成功建议。

### 2026-11-02 重复来源排错与复测

对同一份模拟政策、前 50 位顾问连续取了 3 次真实 `deepseek-flash` 响应：其中 1 次对同一个 `sourceRef` 给出两条不同短引。两条短引本身都在原文中，但程序规定同一来源只能引用一次，因此整条输出会被拒绝。此前提示词没有告诉模型这个唯一性约束；早先浏览器失败的原始响应没有留存，不能断言它必定由此导致。这个样本已能独立复现同类校验失败。

提示词改为 `advice-v2`，明确“每个来源最多一条引用”。程序继续拒绝重复来源、伪造顾问和非原文短引；首次校验失败时只允许重新生成一次，不把模型原文反馈成指令。第二次仍不合格就转人工。两次正常返回的 Token 用量合并计入建议结果；如果调用抛异常，服务商可能已计费但未返回用量，该字段不能当成完整账单。新增测试先证实旧实现不会重试，再验证一次修正成功和两次都不合格时停下。默认 Maven 测试 110 例，失败 0、错误 0、跳过 28。

重新打包并启动本机 Agent 后，沿 `carSystem` 管理员会话、任务刷新、模拟政策检索、真实 DeepSeek 建议、提案发布运行一次：工单 `53` 的 Agent 任务进入 `AWAITING_CONFIRMATION`，候选顾问编号 `9`、一条与模拟政策原文一致的短引，提示词版本 `advice-v2`，提案非空。本次响应记录输入 1024、输出 988 Token；没有确认提案，也没有真实分配。它只是一条成功样本，不代表成功率或稳定性指标。

### 2026-11-03 同范围片段引用边界

同一份模拟政策现在有“申请时间”和“改期”两条片段。工单流程固定核对“试驾申请时间”，因此 `advice-v3` 只把检索首位片段送给模型，并只接受来自该片段、含起止两个时刻的一条原文短引；其他检索候选仍留在只读快照供管理员查看，但页面明确标为“建议未引用”。固定模型输出测试先复现了旧实现把改期片段当作申请时间依据，以及从正确片段引用无关句子的两个错误，再验证修复后都转人工核对。这个时间格式校验是针对当前模拟语料的保守限制，仍依赖首位检索正确，不能单靠逐字短引证明完整语义正确；真实模型新版建议尚未复测。
