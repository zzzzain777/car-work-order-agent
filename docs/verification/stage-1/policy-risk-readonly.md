# 正式建议流程中的只读政策风险提示

日期：2026-11-03。此处政策、门店和车源均为**模拟数据**。本阶段只把政策语义判断接到管理员建议流程，不开放真实工单分配。

## 流程和边界

1. 读取任务快照与政策检索结果，沿用原有门店、车型、有效期和引用校验。首位政策片段仍须包含可解析的每日申请时间窗。
2. 原有结构化建议通过顾问编号、时间窗和政策短引校验后，才判断政策风险。当前版本要求 Agent 任务中有客户本人选店记录；否则直接停在人工核对，不调用风险模型。有记录时，模型输入包含首位政策原文、来源、门店、车型、申请时刻和 `customerSelectionRecorded=true`，不发送客户编号、坐标等个人信息。
3. 第二次模型只返回 `ALLOW`、`DENY` 或 `NEEDS_INFO` 及逐字原文短引。程序拒绝额外字段、伪造短引和无法解析的输出。异常归为 `UNKNOWN`。
4. 已验证客户选店、`ALLOW` 且来源一致时保留候选建议，并明确提醒管理员核对；其余情况降为“需人工核对”，不生成待确认提案。模型不会调用分配接口。
5. 建议运行表记录风险判断、来源、短引、模型用量。确认端复核这条记录；旧提案没有记录时不能恢复或批准。页面展示风险提示和短引，并在恢复时据记录决定是否允许批准。

- 使用本机 PostgreSQL 的定向探针已通过：记录保存、旧提案阻断、只读任务闭环与端到端回放。
- 一次在线 DeepSeek Flash 冒烟测试对现有模拟 `STORE-A` 政策返回 `ALLOW`，引用能在原文中找到；服务商报告输入 350、输出 58 Token。这只证明当前接口能调用和解析，不能证明政策判断正确率。

### 客户本人选店后的失败案例（2026-11-03）

重新为同一本机测试工单建任务，切换到原工单的模拟客户账号。客户页核对归属后，以页面预设的模拟坐标和 2026-11-07 14:00 查询最近五店：`A/B/C/D/E` 按距离排列，`A/C/E` 可选，B 店无车，D 店时段已满。客户点击可选的 `STORE-A`，Agent 任务版本由 0 变 1；管理员切回后看到“客户已选择 STORE-A”。[客户页截图](customer-selection-choice.jpg)。业务系统页面仍显示工单待分配、顾问为空。

管理员随后生成建议。正式政策的门店、车型、生效期和每日 10:00—17:00 时间窗均覆盖这次申请，且客户已选门店，故本案例的**预期政策判断为 `ALLOW`**。实际模型返回 `DENY`，给出的短引却是“可落在每日 10:00（含）至 17:00（不含）”。程序因此将任务停在 `READY_FOR_ADMIN_REVIEW`，没有生成待确认提案。[风险提示截图](customer-selection-risk-review.jpg)。本次请求耗时 2511 毫秒，服务商报告输入 1346、输出 120 Token；仅代表这一次运行。

这属于模型政策判断的误拒，不能计为成功案例。前一次管理员代录同一门店、车型、时刻并命中同一政策时，模型给出 `ALLOW`；两次风险输入的业务字段相同，但没有保留逐字模型请求，不能断言请求字节完全相同或确定随机性来源。“客户已选店”目前也没有作为独立事实传给风险模型；它是需要补充的上下文，但不能单凭这一点解释两次不同结论。引用逐字匹配只能核对出处，无法核对短引是否支持判定。保护行为已验证：错误的 `DENY` 没有触发模拟分配，更没有真实分配。

后续仍需对相同输入重复运行，以区分稳定误判与输出波动；再评估把客户选择证明加入模型输入，并为简单时间窗增加可验证的确定性条件。不能只修改提示词后跑通一次就宣布修复。

### PR09 引用与结论校验（2026-11-03）

已将上面的失败整理为[固定回归输入](../../../data/eval/workflow/policy-risk-contradictory-denial-v1.json)。它保留了现场政策、业务字段和模型返回值；由于当时未保存完整请求，固定输入是按现场证据重建，**不是逐字请求日志**。新增的保守校验仅在模型报 `DENY`、所引文字只有一个无例外的每日允许时段、且申请时刻落在其中时，将风险结果改为 `UNKNOWN`，保留原短引供管理员查错。它不会把模型的错误拒绝改判为 `ALLOW`。

测试先复现 `DENY` 与预期 `UNKNOWN` 的失败，再验证修正通过；时段外的拒绝和引用了额外前置条件的拒绝保持 `DENY`。本轮完整默认测试：152 个发现、110 个通过、42 个按条件跳过、0 失败。客户选择事实仍未单独传入模型，例外条款的语义正确性也不能靠这条窄规则保证；后续须用独立案例验证。

### 客户选店事实进入判断（2026-11-03）

本轮将政策风险提示词升为 `policy-risk-v2`。程序只从 Agent 任务中已有的客户选店记录生成布尔事实；管理员手填门店不等同于客户本人选择，缺记录时直接返回 `UNKNOWN`，不消耗风险模型调用，也不生成待确认提案。客户编号和候选门店快照不发给模型。在线探针只模拟“已验证选店”的布尔输入，不等于一次真实页面闭环。

先新增回归测试，证实旧实现会在缺选店记录时错误返回 `ALLOW`，再实施阻断。完整默认测试：153 个发现、111 个通过、42 个条件跳过、0 失败；数据库回放测试在默认测试中跳过。在线 DeepSeek Flash 使用同一份模拟政策、同一门店车型和申请时刻，连续 3 次得到有原文短引的 `ALLOW`；服务商报告每次输入 392 Token，输出分别为 58、68、68 Token。先前单次探针也得到 `ALLOW`。这只能说明该固定输入在本次小样本中通过，**不是政策判断准确率**；之前的误拒来源仍未确定，复杂例外和真实页面重放尚未复测。

### 真实页面重放：误拒仍会出现（2026-11-03）

使用先前由客户本人选择 `STORE-A` 的 Agent 任务 `6e7b83b9-171e-41ec-9ac1-c8ab7374ccc4`，管理员会话检查通过，页面读取到“客户已选择 STORE-A”。在没有改动门店、车型、申请时刻的情况下重新生成建议，任务版本从 2 增至 3。模型再次返回 `DENY`，但短引仍只是覆盖 2026-11-07 14:00 的每日允许时段；新校验将其降为 `UNKNOWN`，页面显示“模型的拒绝结论缺少支持它的政策引用，需人工核对”，没有生成待确认提案，也没有执行分配。

运行记录 `7546a0c0-9ba0-41d1-97af-ff14a3561bfd` 经管理员只读 `/runs` 接口复查：`outcome=NEEDS_REVIEW`、`riskVerdict=UNKNOWN`，保留原文短引与来源；本次耗时 3844 毫秒，服务商报告输入 1388、输出 106 Token。刷新演示页后任务仍是版本 3 的 `READY_FOR_ADMIN_REVIEW`，但页面不会恢复这条失败建议的文字；运行记录仍能从接口查询。这是展示层待改进点。

结论：加入客户选店事实后，在线单项探针可得到 `ALLOW`，但真实页面仍复现误拒，**不能宣布模型判断问题已修复**。需要保存脱敏的完整风险输入及原始模型输出，比较单项探针与完整流程，并用固定案例评测稳定性；在查明前继续维持 `UNKNOWN` 人工核对。

### 原始交互对比与时区修正（2026-11-03）

新增默认关闭的本机诊断记录器。仅在启动参数 `--agent.policy-risk.diagnostics.enabled=true` 时，把政策风险判断的系统提示、用户输入和原始模型输出写入 Git 忽略的 `target/diagnostics/policy-risk-app.jsonl`；显式在线探针写入同目录的 `policy-risk-probe.jsonl`。这些文件只供本机模拟数据排查，不上传仓库；真实客户资料不得放入诊断输入。记录写入失败不改变业务判断。

对同一任务再次回放发现了可复现的输入差异：完整流程把 2026-11-07 14:00 北京时间序列化为 `2026-11-07T06:00Z`，单项探针传的是 `2026-11-07T14:00+08:00`。两者是同一时刻，但模型面对北京时间政策，前者再次给出 `DENY`，后者连续三次给出 `ALLOW`。系统提示逐字相同，用户输入还存在 JSON 字段顺序差异。**时区表示是有证据的差异和合理的误拒原因推断，不能从这些样本证明它是唯一原因。**

政策风险输入现统一转成 `Asia/Shanghai` 的 `+08:00` 表示，并以固定字段顺序序列化；提示与输入版本记为 `policy-risk-v3`。新增回归测试先复现“同一时刻却生成不同输入”，再验证修正。修正后，完整流程和单项探针的系统提示、用户输入逐字相同（用户输入 SHA-256 前 16 位均为 `6f75fb4a827f8486`），原始模型输出均为 `ALLOW`；服务商均报告风险调用输入 392、输出 58 Token。管理员页面生成顾问 6 的带原文引用建议，任务进入 `AWAITING_CONFIRMATION`，本次完整请求 2774 毫秒、输入 1391、输出 114 Token。没有点击确认或调用真实分配。完整默认测试 156 个发现、114 个通过、42 个条件跳过、0 失败。此处只验证该固定案例的一次完整重放，不能据此宣称模型总体稳定或准确。

## 剩余限制

短引逐字匹配只证明文字出自检索片段，**不能证明模型对例外条款的理解正确**。当前首位政策限定为简单每日时间窗；复杂政策仍需更完整的固定案例和人工复核。真实车源、预约成功、真实分配和生产准确率均未验证。
