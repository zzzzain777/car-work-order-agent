# 七个模拟案例的只读流程回放

日期：2026-11-02。评测对象是当前 Java `ReadOnlyAdviceFlow` 与政策证据门槛；输入为[固定模拟响应](../../../data/eval/workflow/read-only-v1.json)，逐例输出为[保存的结果](../../../data/eval/results/read-only-flow-v1.tsv)。案例卡由 Codex 起草，尚未由项目作者复核或冻结，所以这是**暂定标准答案下的离线回放**。

## 运行方法与口径

在项目根目录用 JDK 21 运行 `mvn -Dtest=ReadOnlyWorkflowEvaluationTest test`。测试固定当前时间为 `2026-10-28T02:00:00Z`，使用同一批模拟工单、管理员、顾问和工作量响应，读取仓库现有六份模拟政策；政策适用性按案例预约时间判断。输入和语料 SHA-256 写在结果文件头，逐例比较预期状态、政策结果、来源引用、顾问编号、缺失字段与只读工具调用次数。完整一致才记 `PASS`。

本项把政策原文片段直接交给证据门槛，以隔离**流程编排与停止条件**；没有调用向量库、Embedding 或真实模型。真实向量检索另有[八例独立记录](policy-rag.md)，不能把两项成绩相乘或合并成完整 Agent 成功率。业务 API 为固定响应替身；C09 在客户端边界模拟业务码 `50000`，本项不验证真实 HTTP 传输。

门店、车型编号和时间由案例直接作为 Agent 补充字段提供；当前工单读取 DTO 没有标题与内容，本项**不评估从客户原话提取信息**。因此下表的“通过”只对应各案例的只读流程切片，不代表案例卡写出的全部业务预期均已实现。
