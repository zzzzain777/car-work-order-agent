# Agent 任务持久化：实现与验证

日期：2026-11-01。新增的是**内部 Java 存储能力**，不是已经开放给浏览器使用的任务流程。

## 已实现

- `policy-rag` 配置组启动时在 Agent 自己的 PostgreSQL 中创建 `agent_task` 表；与政策向量库共用连接，但不写 `carSystem` 数据库。
- 任务保存管理员 ID、工单 ID、试驾待分配状态的最小快照、Agent 补充的门店/车型/时间、版本和状态。Cookie、客户姓名/电话/正文不入库。
- `find`、补充信息更新和预览保存都限定管理员 ID。修改使用数据库 `WHERE version = ?` 条件更新；同一旧版本只能成功一次。补充信息更新同时清空旧预览并回到 `NEEDS_INPUT`。
- 预览只保存模拟政策来源路径、顾问编号及工作量、读取时间；不保存政策全文、顾问姓名或生成的消息。`READY_FOR_ADMIN_REVIEW` 必须同时有政策依据和顾问数据。未经授权、工单编号不匹配或声称允许分配的预览会被拒绝。
- `READY_FOR_ADMIN_REVIEW` 仍只意味着可供人工核对。没有任何流程能从这张表直接执行分配。

## 测试与限制

`bash probes/stage-1/java-pgvector-smoke.sh` 使用临时 PostgreSQL 容器，执行 `JdbcAgentTaskStoreProbeTest` 6 例和原有政策 pgvector 探针 2 例，均通过。任务测试覆盖重建存储对象后读取、管理员隔离、旧版本重放、补充后预览失效、预览精简字段、非法来源、缺证据的就绪状态及超长补充字段。完整 Maven 默认测试在 Java 21 容器中为 80 例、失败 0、错误 0、跳过 13；上述数据库探针需要显式执行，默认测试中被跳过。

当前 `GET /api/agent/preview` 仍返回一次性只读结果，不自动创建任务。还没有任务创建/更新 HTTP 接口，也没有把这张表接到确认或分配。要开放浏览器写操作，先完成同源 Session、Cookie、CSRF、角色撤销新鲜度的真实联调，然后让应用服务从已验证的管理员会话取得管理员 ID，不能信任请求体传入的管理员 ID。真实分配还须解决顾问门店归属、确认前重新读取工单，以及下游超时后结果未知的处理。
