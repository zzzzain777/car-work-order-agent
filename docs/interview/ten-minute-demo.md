# 汽车工单 Agent：10 分钟演示与面试追问

定位：这是**本机模拟原型**。演示要证明检索、状态和安全边界能跑通；确认按钮只接固定拒绝的模拟分配端。

## 演示前准备（不占 10 分钟）

1. 启动 `carSystem:8080`、本地 pgvector 和 Agent `:8091`（`policy-rag,deepseek,bailian-embedding`），确认 `/actuator/health` 为 `UP`。密钥只在本机 Git 忽略的 yml 中。
2. 用明确标为模拟的待分配工单建 Agent 任务；原工单客户在同一浏览器选择五店中的 `STORE-A`，再登录管理员，点击“重新检查”和“刷新任务，查看客户选择”。保留管理员页的任务链接，**现场再点击“刷新证据并生成建议”**。不要把账号、Cookie 或 Key 放进讲稿。
3. 当前门店快照只支持 `MX-7`、`2026-11-07 14:00+08:00`。**2026-11-07 之后不要直接照抄这个时间演示**，先更新模拟快照与对应评测数据，再重新验证。准备好[验收单](../verification/stage-1/resume-demo-acceptance.md)和[逐例结果](../../data/eval/results/README.md)，用于模型服务不可用时如实展示既有记录。

## 现场讲法

| 时间 | 操作 | 你要讲清的一句话 |
|---|---|---|
| 0–1 分钟 | 展示管理员任务页 | “它从独立的 Agent 服务读取 `carSystem` 工单，只在 Agent 库保存补充信息和任务状态。” |
| 1–3 分钟 | 展示客户已选 `STORE-A`、模拟五店说明 | “位置只用于筛最近五家；车和时段是标明虚构的结构化快照，选店不等于预约。” |
| 3–5 分钟 | 点击“刷新证据并生成建议”，看政策来源和顾问工作量 | “先按门店、车型和生效时间过滤，再查 pgvector；模型只在有证据时给候选，引用必须能回到原文。” |
| 5–7 分钟 | 展示任务状态和模拟确认结果 | “提案有版本和 10 分钟有效期；管理员确认前重查工单、政策和顾问，页面不会调用真实分配。” |
| 7–8 分钟 | 展示已保存的[过期提案复测](../verification/stage-1/simulated-confirmation.md#2026-11-03-页面过期提案复测) | “过期返回 `STALE_PROPOSAL`，没有分配尝试；超时则记结果未知，不自动重试。” |
| 8–10 分钟 | 展示[验收数字](../verification/stage-1/resume-demo-acceptance.md#本次收尾核对)和失败案例 | “默认测试 114 通过、42 条件跳过；隔离数据库 33 项通过。五例规则对照与 Agent 同为 5/5，不能说模型提升了准确率。” |

模型若返回“需人工核对”，现场直接展示这条结果和原因；不要切换到历史成功记录后称为本次成功。固定拒绝模拟端返回 `DEFINITELY_FAILED` 是正常演示结果。不要向面试官声称真实预约、真实分配或线上使用。

## 高频追问：用自己的话回答

1. **为什么用显式状态机，没有用 Graph？** 当前主路径和异常分支有限，Java 状态、版本条件更新和数据库记录更容易逐步核对。分支复杂到现有代码难维护时，再比较 Graph 的检查点收益和迁移成本。
2. **这算 RAG 吗？为什么不能直接让模型看全部政策？** 六份模拟 Markdown 被切成七片段并做 Embedding；先筛门店、车型、有效期，再向量检索和核对原文出处。这样能挡住错车型、过期和价格等无依据问题；七片段的小语料不能证明大规模召回质量。
3. **模型到底带来了什么？** 目前它负责只读的结构化建议和政策风险提示，程序约束候选、引用和停止条件。预先冻结的五例中规则与 Agent 结果相同，尚未测出业务增益；这是下一轮语义案例要检验的问题。
4. **Session、CSRF 和越权怎么处理？** Agent 通过同源 Session 调 `carSystem` 只读接口，管理员与客户入口分别验身份和任务归属；写入用会话绑定 CSRF。下游权限撤销修复尚未提交，不能据本机复测宣布生产权限可靠。
5. **重复确认和并发变化怎么办？** 提案绑定任务版本与有效期；本地事务抢占状态并给尝试记录加唯一约束，确认前重新读取工单。真实分配接口没有幂等键和版本参数，所以真实写入仍关闭。
6. **调用超时后为什么不重试？** 超时可能是“业务系统已执行、响应丢了”。先只读重查并记 `OUTCOME_UNKNOWN`，交人工核对；重查结果也不能单独证明本次调用造成了变化。
7. **8/8 检索和 5/5 对照能写成准确率吗？** 不能。它们是作者设计的少量模拟案例，分别检查不同切片；没有真实流量、独立标注或完整 Agent 端到端统计。逐例文件和失败案例都保留，数字只按原范围说。
8. **要接真实分配还缺什么？** 可信实时车源和时段、顾问门店归属、完整工单快照、下游权限修复落地，以及带幂等和并发保护的分配契约。未满足前只能演示模拟确认。

面试前请你亲自脱稿讲清第 2、3、5、6 题；这四题最能暴露是否真的理解项目。若讲不顺，回看[政策检索](../verification/stage-1/policy-rag.md)、[规则对照](../verification/stage-1/structured-advice-blind-v1.md)和[模拟确认](../verification/stage-1/simulated-confirmation.md)，不要背一个虚构的“模型很聪明”故事。
