# 附加设计：附近门店与客户选店

状态：2026-10-28 的第一版业务方案；**已实现纯 Java 最近五家筛选及模拟案例单元测试，尚未实现可用性查询、客户选店、接口、页面、实时车源或预约**。本方案补充[主设计](2026-10-20-car-work-order-agent-design.md)的“缺门店”分支。

## 要解决什么

客户想试驾 `MX-7`，知道预约时间但没有指定门店。系统在客户同意提供位置后，展示距离最近的五家可办理试驾的门店，逐家显示该时间是否有 `MX-7` 试驾车和空闲时段。客户只能选择显示为可用的门店；选店后，管理员流程继续核对该店政策、顾问工作量并生成建议。**选店不等于预约车辆或分配工单。**

车型输入 `MX7` 可以按经过人工确认的别名表归一为 `MX-7`；未知或有歧义的编号要追问，不能交给向量相似度猜测。

## 数据从哪里来

| 数据 | 第一版来源 | 处理原则 |
|---|---|---|
| 客户位置 | 客户主动授权的浏览器定位，或其手动填写的大致位置；离线评测使用虚构坐标 | 拒绝授权仍可手填；只用于本次排序，精确坐标不写进工单、政策库或日志 |
| 门店编号、坐标、是否办理试驾 | Agent 仓库的**模拟结构化门店数据** | 显示“模拟门店”；按直线距离排序，不能称为驾车距离或预计到店时间 |
| `MX-7` 试驾车与时段可用性 | Agent 仓库的**模拟结构化快照** | 记录查询时间及 `AVAILABLE`、无车、时段占满、未知等状态；不是销售库存，也不是实时车源 |
| 试驾政策 | Agent 仓库的版本化模拟原文 | 选店后才按门店、车型编号、预约时间检索；政策可进 RAG |
| 原工单与顾问工作量 | 已授权的 `carSystem` HTTP API | 继续遵守主设计的管理员权限、人工确认和分配门槛 |

2026-10-28 只读核对的 `carSystem` 工单结构没有客户经纬度、门店、试驾车或时段字段，也没有相应查询接口。因此本项目不能声称已查询**真实**试驾车。将来有授权的门店/预约系统接口时，可以用它替换模拟可用性来源；接口契约、刷新频率和失败语义需重新联调，不直接读写 `carSystem` 数据库。

`carSystem` 的顾问列表与工作量返回体也没有 `storeId`。仅凭工作量无法证明某顾问属于客户选定门店。离线案例可以使用明确标为模拟的顾问—门店关系测试后续流程；**真实分配前必须取得可信的顾问门店归属数据，或由管理员核实目标顾问确实服务该店并记录确认**。若无法核实，就停在人工处理，不把“低工作量”说成“该店可接待”。

## 客户看到的流程

1. 先确认计划试驾时间；时间缺失时追问，不能把“某店有 `MX-7` 车”说成“这个时段可试驾”。客户可授权定位，也可手填位置；两者都没有时等待补充。
2. 从营业且办理试驾的门店中，按客户位置的**直线距离**取最近五家。先确定这五家，再逐家查询指定车型与时段的可用性；第六近的门店不能偷偷替换进首批五家。
3. 展示五家门店的距离、可用状态和快照时间。只有试驾车与时段都可用的门店能选；查询失败显示“暂无法确认”，不能当作可用。若五家都不可用，提示换时间或由客户明确选择扩大范围。
4. 客户选店时再核查其身份、工单归属和该店可用性。若车或时段已变化，保留工单待选状态、刷新候选，说明需要重新选择；不能悄悄改选其他店。重复提交同一选择只返回同一任务结果。
5. 将客户选定的 `storeId`、选择时间和可用性快照标识保存在 Agent 任务中；不修改 `carSystem` 原始工单。之后才进入该店政策检索、顾问查询和管理员确认。最终分配前再核查时效与必要的外部状态；即使分配成功，也不能展示“试驾已预约”。

离线原型可以用固定的“客户选择事件”验证上述流程。真正让客户在页面上选择时，应复用已验证的同源登录态，确认当前客户是该工单的 `customerId`，并验证客户写请求的 CSRF 与任务版本。现有管理员 Session 方案不能直接当作客户授权；这些身份与 Cookie 行为要在联调中单独验证。若先由管理员代客户录入选择，界面与审计必须标为“管理员代录”，不能写成“客户已点击选择”。

## 控制边界与验收

- 最近五家排序、车型编号映射、可用性判断和选择权限由确定性程序处理；模型不能自行编造门店、车源、距离或可用时段。RAG 只回答选定门店的**政策**问题。
- 客户位置被拒绝、没有时间、五家全不可用、可用性查询失败、客户越权、选择时可用性变化、并发重复选择，都有可复跑的停止或刷新结果。
- 真实门店车源和顾问门店归属若无可信数据，不能把模拟结果作为真实可执行分配依据；这些限制在演示和面试中如实说明。
- 展示的五家必须是固定输入中最近的五家；不可用或未知状态不可选；客户选择只能写入 Agent 任务；管理员确认前 `carSystem` 分配 POST 次数为 0。
- 模拟数据与实测结果分开报告；用模拟可用性通过案例不能证明真实门店有车，也不能写成线上预约成功。
