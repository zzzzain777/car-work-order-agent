# 本机任务演示入口设计

日期：2026-11-02。此入口把已经验证的内部任务、只读证据、模型建议与模拟确认连接成可点击流程。它服务于本机演示和逐步核对，不开放真实工单分配。

## 方案取舍

- 推荐并采用：沿用 `policy-rag,deepseek,bailian-embedding` 下已有的 PostgreSQL、模拟政策检索、DeepSeek 建议和 `carSystem` 只读客户端，新增本机 HTTP 任务入口与简洁页面。优点是演示确实经过已实现的链路；代价是需要本机数据库、模型配置以及管理员已登录的 `carSystem`。
- 未采用：另造全假数据的一键离线演示。它容易启动，但容易把规则替身误看成真实 RAG/模型结果。
- 未采用：立刻接真实分配。旧 Session 权限新鲜度、CSRF 同源联调、顾问门店归属与真实车源仍未满足设计门槛。

## 行为

浏览器访问本机 `http://localhost:8091/agent-demo.html`；使用同一 `localhost` 主机名登录本机 `carSystem`，使 `/api` 路径的 `SESSION` Cookie 能发给 Agent。页面依次完成：创建待分配试驾任务 → 保存门店/车型/时间 → 刷新政策和顾问证据、生成有引用的候选 → 展示提案和有效期 → 管理员批准或拒绝。批准只进入模拟分配端；它不发送真实 `POST /api/workOrder/assign`。模拟端返回“拒绝”，用于展示确定失败和一次性尝试；正常成功、超时和并发分支继续由隔离数据库测试验证。

任务 HTTP 接口只在上述三个 Profile 同时启用时出现。所有任务请求都按 Cookie 调用当前身份检查；写请求要求 `Origin` 与本机页面完全同源，并要求服务端签发、绑定 `SESSION` Cookie、短时有效的 CSRF Token。Cookie/Token 不进入数据库、模型输入或日志。提案和任务版本失败返回冲突，不重发模拟分配。响应只含 Agent 任务、模拟政策依据、顾问工作量、建议和状态；页面显眼标注模拟性质。

## 验收

接口测试覆盖无 Cookie、跨源、缺失/篡改 Token、跨管理员、陈旧版本、拒绝与重复确认；隔离数据库测试仍覆盖确认的并发与未知结果。默认配置不出现任务写入口，只有显式启用上述 Profile 才能演示。页面可顺序操作并显示错误及当前状态，但不把“模拟失败”说成真实分配结果。
