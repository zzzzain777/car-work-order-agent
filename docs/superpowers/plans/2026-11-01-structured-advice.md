# 结构化建议与引用核验计划

**目标：** 模型只从本次只读预览的顾问和模拟政策证据中选择候选；Java 校验结构、顾问编号和逐条原文引用，输出供管理员核对的建议。

**现状：** `ModelTextGenerator` 已通过 Spring AI 接入低价 DeepSeek 模型；`AgentTaskWorkflow.Refresh` 包含任务和只读证据，但模型尚未接入。

**设计：** 新增纯 Java `StructuredAdviceService`。它只接受状态为 `READY_FOR_ADMIN_REVIEW`、任务版本与预览一致的刷新结果。发送给模型的上下文仅含工单编号、Agent 补充字段、模拟政策来源与原文、顾问编号及工作量；不含 Cookie、管理员 ID、顾问姓名或客户信息。模型返回 JSON：候选顾问 ID 和若干政策引用（来源路径、原文短引）。程序验证顾问在本次结果中、来源在本次证据中、每条短引是对应原文的精确片段，才用程序模板生成建议。模型失败或任何校验失败时返回 `NEEDS_REVIEW`，不生成可确认或可分配的结果。提示词版本、模型名和 Token 用量随结果返回，供后续评测记录。

**取舍：** 模型选择候选与引用，政策性表述直接展示经过核对的原文短引。这样能验证证据边界，避免把未经语义核验的模型改写当成事实。该建议仍需管理员核对顾问门店归属；不开放分配。

## 实施与验收

1. 先测试非就绪状态不调用模型、正确 JSON 生成候选、伪造来源/短引/顾问被拒、模型异常降级、发送上下文不含身份和姓名。
2. 在 `ModelTextGenerator` 增加分开的系统消息和用户消息，并用现有本地假 DeepSeek 服务验证消息角色。
3. 将服务作为 `policy-rag` 与 `deepseek` 同时启用时的可选 Bean；跑完整 Maven 测试，不使用真实 Key。
4. 更新验证记录，提交推送；不把单次假模型测试写成建议质量评测。
