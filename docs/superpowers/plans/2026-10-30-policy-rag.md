# 模拟政策 RAG 最小闭环实施计划

日期：2026-10-30。基于已确认的第一版设计；本次只实现模拟政策入库和只读检索，不生成业务结论，也不调用 `carSystem`。

## 接口与边界

- 显式启用 `policy-rag,bailian-embedding` 后，主应用使用本机 PostgreSQL + pgvector 和已配置的百炼 Embedding；默认 Profile 不连接数据库或模型。
- `POST /api/policies/search` 接受 `storeId`、`modelCode`、`appointmentAt`、`question`，返回 `outcome`、模拟标记和可追溯的政策片段。只监听本机地址。
- 先按门店、车型编号和时间筛选原始政策；无适用政策直接返回，无需向量请求。多份同范围有效政策交人工，不由相似度选赢家。单份政策才执行限定 policyId/version 的向量检索，再用原文和元数据校验结果。
- 索引只存本仓库模拟政策。固定 1024 维、精确检索和专用向量表；重启时相同语料跳过重新生成 Embedding。语料变化时更新索引，保留原始 Markdown 作为最终引用依据。

## 工作顺序

1. 写一个不调用真实模型的失败用例，覆盖适用政策、错车型、过期、冲突和错误片段；实现最小查询服务，验证规则先于向量检索。
2. 增加独立的 RAG Profile、pgvector 接线、本地私有数据库配置和只读 HTTP 接口；补自动索引与重启跳过机制。
3. 用本地 Docker 数据库及真实免费 Embedding 做一次端到端验证；固定案例逐例记录检索与引用结果，不把单次结果当作完整准确率。
4. 将 Java 代码、测试、配置和脚本中的英文注释、异常提示及面向读者的说明改为中文；保留 Java 标识符、政策元数据键、协议字段和稳定的测试快照格式。
5. 跑全套测试，检查密钥未进入可提交文件，再以中文 `feat` 提交并推送。

## 验收

- 有效 `STORE-A/MX-7` 查询可返回仓库内对应政策来源；`MX-70`、过期、无依据和冲突情况不会误给可确认政策。
- 对单份政策执行检索时，数据库过滤只允许已通过结构化筛选的政策 ID 与版本；所有返回片段通过原文核对。
- 相同语料第二次启动不重算全部向量；本地私有 Key 与数据库密码仍被 Git 忽略。
- 默认测试集无需 Docker 或付费接口；显式端到端验证记录真实模型 ID、语料、结果和局限。
