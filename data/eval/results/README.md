# 政策检索离线结果

[`keyword-baseline-v1.tsv`](keyword-baseline-v1.tsv) 是 Java 评测测试实际运行后保存的结果，不是人工填写的成绩。输入是 [`keyword-baseline-v1.tsv`](../retrieval/keyword-baseline-v1.tsv) 和本仓库六份模拟政策；文件头记录了两组输入的 SHA-256。

另有先固定标准答案再运行的[挑战集输入](../retrieval/keyword-holdout-v1.tsv)、[逐例核对依据](../retrieval/keyword-holdout-v1-review.md)和[运行结果](keyword-holdout-v1.tsv)。挑战集使用同一份模拟政策，换用同义问法、无依据问题和时间边界；本版标准答案不按运行结果修改。编题时已看过当前实现，因此它是针对实现弱点的挑战集，不是独立抽样或真正的盲测。

在 IDEA 运行 `PolicyRetrievalEvaluationTest`，或在项目根目录运行 `mvn -Dtest=PolicyRetrievalEvaluationTest test`。每次分别把结果写到 `target/eval/keyword-baseline-v1.tsv` 和 `target/eval/keyword-holdout-v1.tsv`，再与这里保存的版本比较。若结果变化，先检查原因；新一轮实验应保留旧结果并另存新版本。**测试通过仅表示重放结果与保存快照一致，不表示挑战集全部答对。**

- `exactCasePass`：预期状态、政策 ID 集合和引用路径集合全部相同的案例数／总案例数。
- `recallAt2`：预期有政策的案例中，全部正确政策 ID 出现在前两个检索片段的案例数／此类案例数。
- `rankedHits`：按关键词分数排序的片段 ID 与分数；分数只用于当前关键词基线的顺序。

旧五例的政策 ID、引用和时间适用性已由 Codex 对照六份模拟原文复核；它们仍是**尚未由项目作者复核或冻结的模拟业务案例草稿**，其中 C01 与 C04 使用同一份政策。结果只说明这次小样本检索重放的表现，不能称为通用准确率、完整 Agent 成功率或真实业务联调结果。

挑战集本次逐例结果为 **6/8 完全符合预期、Recall@2 为 3/4**。两个失败保留在结果文件中：H01 的“试车”未召回试驾政策；H02 的价格问题仅凭 `STORE-A` 和 `MX-7` 两个标识符命中试驾政策，不能作为价格依据。H05 虽按“多份政策交人工”通过，两份片段的关键词分数都为 0；它只验证了多政策保护分支，**没有验证文本冲突识别**。H06、H07 检出政策也不等于该时刻允许试驾。

因此，当前关键词方案不能单独承担无依据拒答或同义问法召回。已在相同八个案例上跑通[真实向量模型和 pgvector 的逐例结果](policy-rag-holdout-v1.tsv)，详情见[联调记录](../../../docs/verification/stage-1/policy-rag.md)。旧关键词失败结果仍保留；新结果主要证明范围、拒答和出处检查可运行，不能由这组小样本推断复杂语料的语义排序质量。

下一轮检索验收至少要求：H01 正确政策进入前两条并带原文引用；H02 不以试驾条款回答价格或优惠；H03/H04/H08 不返回过期或错误车型政策；H05 同时保留两份政策交人工处理；旧五例不退化。H02 的 `NO_KEYWORD_MATCH` 是关键词基线里表达“没有支持该问题的命中”的预期状态，向量接口对应 `NO_EVIDENCE`；这不表示用户输入没有任何词面重合。下一轮还须扩展独立案例与证据支持检查。
